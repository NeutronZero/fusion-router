## Executive Architecture Charter & AF-003 Governance Policy

> **FusionRouter is an orchestration platform, not a collection of features. Every subsystem must communicate through stable contracts (APIs, events, repositories, or the Execution ABI), and no layer may bypass the compiler-driven orchestration model.**
>
> **AF-003 Governance Policy:**
> - No new architecture discussions unless an ADR proposes a change.
> - No new crates without updating the dependency matrix and conformance tests.
> - No breaking changes to versioned contracts without incrementing version tags and documenting migration paths.
> - No implementation that violates architecture laws or invariants.

---

## 1. Architecture Laws (Laws 1–17)

- **Law 1 (Compiler Primacy):** *The compiler is the single source of truth for planning and execution.* All user requests compile down to an `ExecutionGraph` DAG.
- **Law 11 (State Decoupling):** *The UI never directly mutates runtime state.* Everything flows through versioned REST (`/api/v1/*`) or WebSocket (`/ws/events`) APIs in the Studio API Gateway.
- **Law 12 (Reproducibility):** *Every execution is reproducible.* Replaying a recorded `EvidenceSnapshot` through the compiler produces identical `ExecutionGraph` DAGs.
- **Law 13 (Explainability):** *Every routing decision is explainable.* All multi-dimensional routing scores (capability, budget, latency, health, policy) are explicitly exposed and recorded.
- **Law 14 (Configuration Versioning):** *Every configuration change is versioned.* Mutations save a `ConfigVersion` snapshot with 1-click rollback capability.
- **Law 15 (Plugin Boundaries):** *Every external integration is implemented as a plugin.* Provider-specific SDKs and strategies never leak into `fusion-compiler`.
- **Law 16 (Stable Contracts):** *Every interaction between architectural layers must occur through a versioned contract.* No layer may depend on another layer's internal implementation details.
- **Law 17 (Platform Independence):** *The Fusion Platform Kernel must remain independent of transport, storage, user interface, provider implementations, and deployment topology. Only versioned contracts may cross the kernel boundary.*

## 2. Architectural Invariants (`docs/architecture/invariants.md`)

- **Invariant 1:** `WorkflowIR` is immutable after construction.
- **Invariant 2:** `ExecutionGraph` is immutable after compilation.
- **Invariant 3:** Compiler passes are 100% deterministic.
- **Invariant 4:** Planner never invokes external providers directly.
- **Invariant 5:** Workers never perform workflow planning.
- **Invariant 6:** Repositories never contain domain business logic.
- **Invariant 7:** `fusion-kernel` has zero infrastructure dependencies.
- **Invariant 8:** Every public contract is versioned (`v1`).
- **Invariant 9:** Every execution has a unique, strongly-typed `ExecutionId`.

---

## 3. Subsystem Responsibility Boundaries

- **Platform Kernel (`fusion-kernel`):** Owns platform invariants, Event Bus, Context System, Resource Manager, Capability System, System Catalog, and Health Engine. Extended via versioned interfaces (`Kernel API v1`), never modified breakingly.
- **Capability System (`fusion-kernel/capability`):** Structured taxonomy (`Reasoning`, `Vision`, `ToolUse`, `Artifacts`, `Search`, `LongContext`) with identifier, version, dependencies, compatibility rules, and query engine.
- **Planner (`fusion-planner`):** Takes (`Intent`, `Capability Graph`, `Policies`, `Configuration`) -> Outputs `WorkflowIR v1`. Never calls providers.
- **Compiler (`fusion-compiler`):** Takes `WorkflowIR v1` -> Optimizes & Emits `ExecutionGraph`. Passes are 100% deterministic.
- **Scheduler (`fusion-scheduler`):** Implementations of `Scheduler` trait (`Sequential`, `Parallel`, `Budget`, `Latency`).
- **Runtime (`fusion-runtime`):** Executes nodes, retries, checkpoints, streams output, and emits telemetry. Never classifies or plans.
- **Coordinator:** Assigns work, monitors workers, aggregates telemetry, replays, and checkpoints. Never compiles or plans.
- **Worker (`fusion-worker`):** Executes ABI, calls providers, streams output, uploads evidence. Never schedules or plans.

## 6. Release Governance Policy & v1.0 Exit Criteria

### Release Policy
- **Minor Release (0.x):** May add APIs, plugins, or scheduler implementations. Must NOT break existing `v1` contracts.
- **Major Release (1.0+):** Required when breaking contracts (e.g. `WorkflowIR v2`, `Execution ABI v2`). Requires explicit migration paths.

### v1.0 Exit Criteria
- **Architecture:** Laws 1–17 and Invariants 1–10 100% compliant with zero conformance failures.
- **Compiler:** `WorkflowIR v1` & `Execution ABI v1` frozen and benchmarked.
- **Runtime:** Distributed coordinator/worker runtime stable with deterministic replay.
- **Studio:** Complete web studio with Provider Manager, Diagnostics, Replay, Explain Route, and Plugin UI Extensions.
- **Testing:** Unit, Integration, Replay, Performance, and Architecture Conformance suites green in CI.

## 7. Phase-by-Phase Execution Roadmap

### Phase 1: Workspace Tier Setup, Manifest & Governance Docs
- Create root `Cargo.toml` workspace with Tier 1 (Foundation), Tier 2 (Engine), Tier 3 (Platform), and `apps/fusion-server`.
- Create `docs/architecture/manifest.yaml`, `docs/architecture/invariants.md`, ADR-001..008, and `docs/governance/`.
- Build Architecture Conformance Suite (`tests/conformance.rs`) checking `manifest.yaml` and the 3-Tier dependency direction.

### Phase 2: Foundation & Infrastructure Implementation
- Build `fusion-core` and `fusion-kernel` (Event Bus, Capability System, Contexts, Resource Manager, System Catalog, Health Engine).
- Build `fusion-infrastructure` SQLite repositories (`Database Schema v1`), `SecretManager`, and telemetry persistence.
- Implement CQRS `CommandBus` and `QueryBus` in `fusion-api-public`.

### Phase 3: Domain Engine Implementation & Worker ABI
- Implement `fusion-compiler` passes, pipeline, and `Explain Route` scoring.
- Implement `fusion-planner` strategy lowering over `CapabilitySystem`.
- Implement `fusion-scheduler` traits (`Sequential`, `Parallel`, `Fallback`).
- Implement `fusion-runtime` DAG checkpointing and `fusion-worker-protocol` worker self-registration.

### Phase 4: Studio API Gateway & Embedded UI Studio
- Build `fusion-studio-api` application service layer and REST `/api/v1/*` routes.
- Build `ui/` React + TS Studio with Design Tokens, Persona Navigation, and UI Extension SDK mount points.
- Wire Bootstrap Sequence and static asset embedding in `apps/fusion-server`.

### Phase 5: Diagnostics, Observability & Certification
- Build Replay Engine in `fusion-infrastructure`.
- Build 1-Click System Check diagnostics and offline AI Setup Assistant.
- Run complete Conformance Suite (`cargo test --test conformance`) to certify 100% compliance with AF-003.
