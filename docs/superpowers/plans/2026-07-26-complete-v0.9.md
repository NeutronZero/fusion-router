# v0.9 Completion Implementation Plan

> **For agentic workers:** This plan is executed via parallel stream dispatch.

**Goal:** Complete all Phase 2 and Phase 3 items in the v0.9 roadmap.

**Architecture:** Four parallel work streams: (A) compiler optimization passes, (B) documentation/ADRs, (C) runtime enhancements, (D) platform & polish. Stream A is sequential; B/C/D are independent of A and each other.

**Tech Stack:** Rust, cargo, serde, tokio, wasmtime, prometheus

---

## Work Streams

### Stream A: Compiler Optimization (sequential — 5 days)

Depends on ADR-020. Three sequential tasks:

- **A1**: Extend `OptimizationPass` trait (add `goal()`, `preconditions()`, `postconditions()`) and update `OptimizationPipeline` for rollback safety
- **A2**: Dead Node Elimination pass (TDD — write tests first, then implement)
- **A3**: FanOut Consolidation pass (TDD)

### Stream B: Documentation (parallel — 3 days)

Five independent documentation tasks:

- **B1**: Clarify ResourceGuard contract — investigate RAII Drop semantics at `pipeline.rs:167-168`, document in code or ADR
- **B2**: Define provenance schema — specify fields on `ExecutionResult` (graph hash, PrimitiveGraph version, pass manifest, strategy descriptor)
- **B3**: Operator docs — deployment guide, Dockerfile, scaling guidance
- **B4**: ADR-007 through ADR-012 — document missing architectural decisions (research existing code/docs, summarize)

### Stream C: Runtime Enhancements (independent — 4 days)

- **C1**: Artifact trait integration — wire typed artifacts through execution model
- **C2**: FusionStrategy refinement — dynamic sub-strategy selection based on model availability

### Stream D: Platform & Polish (sequential — 8 days)

- **D1**: User-facing logging and monitoring — per-strategy latency histograms, error rates, graph hash distribution on `/metrics`
- **D2**: WASM plugin wiring — connect `wasmtime` runtime to `PluginManager`
- **D3**: Benchmark suite expansion — strategy-specific benchmarks
- **D4**: Remove dead code paths — clean up remaining dead abstractions

---

## Execution Order

1. Dispatch Stream B (docs) to parallel agents — fully independent
2. Execute Stream A (optimization) inline — TDD, sequential
3. Dispatch Stream C (runtime) after Stream A is stable
4. Dispatch Stream D (platform) last
