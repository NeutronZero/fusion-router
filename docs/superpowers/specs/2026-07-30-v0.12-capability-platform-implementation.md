# FusionRouter v0.12 — Capability Platform Implementation Specification

**Date:** 2026-07-30
**Status:** Draft
**Supersedes:** Sprint O3, O3.5, O4, O5, O6 individual sprint specs

---

## 1. Overview

FusionRouter v0.12 completes the Capability Platform — the architectural layer that allows capabilities to be authored, packaged, sandboxed, resolved, and governed as first-class citizens of the runtime. This specification defines the remaining subsystems needed to ship v0.12:

| Subsystem | What it delivers | Foundation |
|-----------|-----------------|------------|
| **Capability Runtime** | WASI sandboxed execution of capability WebAssembly modules | ADR-019 |
| **Host Interface** | 5 host services (events, logging, secrets, HTTP, metrics) exposed to sandboxed capabilities | ADR-019 |
| **Package Platform** | `.fusionpkg` format, verification, loading, and registry integration | ADR-018 |
| **Developer Platform** | CLI toolchain: scaffold, build, test, publish, dev loop | — |
| **Operations Platform** | Observability dashboard + governance UI for registry, policy, attestation | — |

### Relationship to ADRs

This document does not repeat ADR-018 or ADR-019. Those remain canonical for the package format and host service interface respectively. Where decisions have not previously been recorded, this specification defines them.

### Retired Terminology

"Sprint O3", "O3.5", "O4", "O5", and "O6" are retired as planning constructs. The remainder of v0.12 is organized by subsystem, not by sprint boundary. Implementation order follows the dependency graph:

```
Runtime → Host Interface → Packaging → CLI → Operations
```

## 2. Glossary

| Term | Definition |
|------|-----------|
| **Capability** | A well-defined, sandboxed unit of functionality — e.g., file read, HTTP fetch, secret access. Each capability has a unique `CapabilityId`, a version, and a declared set of permissions. |
| **Capability Contract** | The metadata structure (`CapabilityContract`) that describes what a capability does, its inputs/outputs schemas, declared permissions, dependencies, and estimated resource usage. |
| **Capability Instance** | A runtime handle bound to a specific `CapabilityContract` after resolution. Holds an `Arc<dyn CapabilityPlugin>` for native execution or a compiled WASM module for sandboxed execution. |
| **Capability Package** | A `.fusionpkg` archive containing a compiled WASM module, its manifest, and a cryptographic attestation. The distribution unit for capabilities. |
| **Sandbox Instance** | A running wasmtime instance created from a compiled WASM module. Ephemeral — each invocation gets a fresh instance. |
| **ExecutionGraph** | The final IR produced by the compiler pipeline. Consumed by the scheduler. Contains ordered `ExecutionNode`s with resolved models, retry policies, and deterministic UUIDs. |
| **Host Services** | The 5 runtime services (`emit_event`, `log`, `fetch_secret`, `http_request`, `record_metric`) exposed to capabilities through `CapabilityHostServices`. |
| **RuntimeModuleCache** | An in-memory cache of compiled wasmtime modules, keyed by `(CapabilityId, Version)`. Avoids recompilation on repeated invocations. |

## 3. Architecture

### System Pipeline

The Capability Platform extends the existing FusionRouter pipeline with new stages between the Resolver and Scheduler:

```
Developer
    │  [fusion new, build, test, publish]
    ▼
.fusionpkg
    │
    ▼
PackageVerifier
    │  [attestation verification, permission audit]
    ▼
PackageLoader
    │  [metadata extraction, registration]
    ▼
CapabilityRegistry (frozen)
    │
    ▼
CapabilityResolver (frozen)
    │
    ▼
CapabilityGraph
    │
    ▼
CapabilityGraphLowerer
    │
    ▼
ExecutionGraph
    │
    ▼
Capability Runtime (SandboxRuntime)
    │  [wasmtime instantiation, memory limits, isolation]
    ▼
CapabilityHostServices
    │  [events, logging, secrets, HTTP, metrics]
    ▼
Telemetry / EventBus
```

### Layer Ownership

| Layer | Component | Owner |
|-------|-----------|-------|
| 1 | `SandboxRuntime` trait + `WasmtimeSandboxRuntime` | Runtime |
| 2 | `CapabilityHostServices` trait | Host Interface |
| 3 | `WasmtimeCapabilityHost` | Host Interface |
| — | `RuntimeModuleCache` | Runtime (shared) |
| 4 | `PackageVerifier`, `PackageLoader`, `PackageRegistry` | Package Platform |
| 5 | `fusion new`, `build`, `test`, `publish`, `dev` | Developer Platform |
| 6 | Dashboard, Runtime Inspector, Governance UI | Operations Platform |

### Key Architectural Invariants

1. The `CapabilityRegistry` trait and `InMemoryCapabilityRegistry` are frozen — no structural changes.
2. The `CapabilityResolver` and `CapabilityGraph` are frozen — no structural changes.
3. All sandbox interactions go through `CapabilityHostServices` — capabilities never access FusionRouter internals.
4. `.fusionpkg` packages are immutable after publishing — versioning is the only update mechanism.
5. The old C-ABI shared library plugin system is deprecated but not removed in v0.12.

## 4. Capability Runtime

### RuntimeContext

Execution metadata passed to every `instantiate` call. Encapsulates fields likely to grow over time without changing the trait signature.

```rust
pub struct RuntimeContext {
    pub execution_id: Uuid,
    pub host_services: Arc<dyn CapabilityHostServices>,
    pub deadline: Option<tokio::time::Instant>,
    pub telemetry: Arc<dyn TelemetryContext>,
    // Future: cancellation_token, policy_snapshot, scheduler_context
}
```

For v0.12, `execution_id`, `host_services`, and `telemetry` are always populated. `deadline` is optional.

### SandboxRuntime Trait

Adapted from ADR-019 to accept `RuntimeContext` instead of expanding the parameter list:

```rust
#[async_trait]
pub trait SandboxRuntime: Send + Sync {
    fn name(&self) -> &'static str;
    async fn instantiate(
        &self,
        module_bytes: &[u8],
        ctx: RuntimeContext,
    ) -> Result<Box<dyn SandboxInstance>, RuntimeError>;
}
```

### WasmtimeSandboxRuntime

The shipped implementation uses `wasmtime` with the following configuration:

- **Engine:** `wasmtime::Engine::new(wasmtime::Config::new().wasm_reference_types(true).wasm_bulk_memory(true))`
- **Memory limit:** 64 MB default, configurable per-capability via `CapabilityContract.estimated_memory_bytes`
- **Fuel metering:** Enabled for deterministic execution budgeting (configurable fuel, default 1M units)
- **WASI:** `wasmtime_wasi::WasiCtx` with virtual pre-opened directories (none by default)
- **Ephemeral instances:** Each invocation gets a fresh `Instance` — no instance reuse across calls

### SandboxInstance Trait

```rust
#[async_trait]
pub trait SandboxInstance: Send {
    async fn invoke(&mut self, input: &[u8]) -> Result<Vec<u8>, RuntimeError>;
    fn reset(&mut self) -> Result<(), RuntimeError>;
    fn memory_usage(&self) -> u64;
    fn fuel_consumed(&self) -> u64;
}
```

### NativeSandboxRuntime (Dev Only)

A non-sandboxed implementation owned by the Developer Platform (not the Runtime). Used for fast iteration during development. It loads capability logic as native Rust trait objects:

```rust
pub struct NativeSandboxRuntime {
    capabilities: HashMap<CapabilityId, Box<dyn CapabilityPlugin>>,
}
```

This is explicitly a dev-only adapter. Production deployments MUST use `WasmtimeSandboxRuntime`.

### Compilation vs. Instantiation

WASM module compilation and instance creation are distinct operations:

```
Package load
    │
    ▼
Compile Module (wasmtime::Module::new)
    │  Heavy: validates, parses, JIT-compiles
    ▼
Cache Module (RuntimeModuleCache)
    │  Keyed by (CapabilityId, Version)
    ▼
Instantiate (wasmtime::Instance::new)
    │  Light: allocates linear memory, binds imports
    ▼
Invoke
    │
    ▼
Destroy (Drop)
```

`WasmtimeSandboxRuntime` SHALL cache compiled modules in a `RuntimeModuleCache` to avoid recompilation on repeated invocations. Instances remain ephemeral — each invocation creates and destroys its own `Instance` from the cached module.

### Instance Lifecycle

```
Module already cached? ──no──► Compile + cache
    │ yes
    ▼
Instantiate (WASI ctx, linker imports, fresh memory)
    │
    ▼
invoke(input) ──► output
    │
    └── Drop ──► (fuel/memory stats finalized)
```

- `instantiate` creates a WASI context, sets up linker imports, allocates linear memory, and returns a `SandboxInstance`.
- `invoke` calls the capability's entry function (`capability_invoke` exported function receiving/returning JSON bytes).
- `reset` clears WASI state and reinitializes memory (not supported in v0.12 initial implementation — returns `NotSupported` error).
- `memory_usage` and `fuel_consumed` are reported as metrics and surfaced in operations.

### Error Handling

| Condition | Error | Handling |
|-----------|-------|----------|
| WASM compilation failure | `RuntimeError::CompilationFailed` | Package rejected at load time |
| Memory exceeds limit | `RuntimeError::OutOfMemory` | Instance killed, event emitted |
| Fuel exhausted | `RuntimeError::FuelExhausted` | Instance killed, event emitted |
| Trap during execution | `RuntimeError::ExecutionTrap { message }` | Instance killed, trap message recorded |
| Host function returns error | `RuntimeError::HostServiceError { service, inner }` | Trap propagated to WASM, then handled |

### File Organization

```
src/
  runtime/
    mod.rs                  — RuntimeError, re-exports
    sandbox_runtime.rs      — SandboxRuntime trait
    wasmtime_runtime.rs     — WasmtimeSandboxRuntime
    sandbox_instance.rs     — SandboxInstance trait
    config.rs               — SandboxConfig (memory, fuel, timeouts)
    module_cache.rs          — RuntimeModuleCache
```

## 5. Host Interface

### Two-Layer Architecture

```
CapabilityHostServices (abstract trait, ADR-019)
        │
        ▼
WasmtimeCapabilityHost (concrete, wires services to WASM imports)
        │
        ▼
Linker Imports (wasmtime::Linker bindings for 5 host functions)
```

### CapabilityHostServices Trait

As defined in ADR-019:

```rust
#[async_trait]
pub trait CapabilityHostServices: Send + Sync {
    async fn emit_event(&self, event: ExecutionEvent) -> Result<(), GateError>;
    async fn log(&self, level: tracing::Level, message: &str);
    async fn fetch_secret(&self, secret_name: &str) -> Result<String, GateError>;
    async fn http_request(&self, req: reqwest::Request) -> Result<reqwest::Response, GateError>;
    fn record_metric(&self, name: &str, value: f64);
}
```

### WasmtimeCapabilityHost

Concrete implementation that:

1. Receives `Arc<dyn CapabilityRegistry>` for secret resolution
2. Receives `Arc<EventBus>` for event publication
3. Receives `reqwest::Client` for outbound HTTP
4. Receives `Arc<FusionMetrics>` for metric recording
5. Creates per-invocation correlation context (linking events back to the execution)

### Linker Imports

Each host function becomes a wasmtime `Linker` import:

| WASM Import | Host Function | Policy Gate |
|-------------|--------------|-------------|
| `host.emit_event` | `emit_event` | None (always allowed) |
| `host.log` | `log` | None |
| `host.fetch_secret` | `fetch_secret` | `Permission::Secrets` |
| `host.http_request` | `http_request` | `Permission::Http` |
| `host.record_metric` | `record_metric` | None |

### Policy Enforcement

`Permission::Secrets` and `Permission::Http` are enforced at the `WasmtimeCapabilityHost` level, not in the capability code:

- If the capability's `CapabilityContract.permissions` does not include `Secrets(["db_password"])`, calling `fetch_secret("db_password")` returns `GateError::PermissionDenied`.
- If the capability's contract does not include `Http(["https://api.example.com/*"])`, calling `http_request` to a non-matching URL is rejected.

This mirrors the policy pass already implemented in the compiler (`PolicyCompilerPass` in `src/compiler/passes/policy.rs`).

### File Organization

```
src/
  runtime/
    host_services.rs        — CapabilityHostServices trait
    wasmtime_host.rs        — WasmtimeCapabilityHost
    linker.rs               — Wasmtime linker setup for 5 imports
    policy.rs               — Permission checking helpers for secrets/HTTP
```

(Shared under `src/runtime/` with the Runtime because they are tightly coupled at the instance level.)

## 6. Package Platform

### Package Format (.fusionpkg)

As defined in ADR-018:

```
archive.fusionpkg
  ├── manifest.toml
  ├── module.wasm
  └── attestation.json
```

`manifest.toml` contains:
- `name`, `version` (SemVer)
- `capabilities` — list of `CapabilityContract` definitions exposed by this package
- `dependencies` — references to other capabilities by `CapabilityId` + `VersionReq`
- `permissions` — the full set of `Permission` values this package requires

### PackageVerifier

Responsibility: validate a `.fusionpkg` before it enters the system.

```rust
pub struct PackageVerifier {
    verifier: Arc<dyn Signer>,
}

impl PackageVerifier {
    pub fn verify(path: &Path) -> Result<VerifiedPackage, PackageError> {
        // 1. Extract and parse manifest.toml
        // 2. Verify attestation.json signature via Signer trait
        // 3. Validate WASM module compiles (dry run in wasmtime)
        // 4. Confirm declared permissions match WASM imports
        // 5. Return VerifiedPackage (opaque, verified wrapper)
    }
}
```

Steps:
1. **Structural integrity** — valid gzipped tarball, all required files present
2. **Attestation verification** — `attestation.json` signature checked against the ecosystem's trusted signer set
3. **WASM compilation check** — module compiles in wasmtime (no execution)
4. **Permission consistency** — the set of `Permission` values declared in `manifest.toml` is compared against the WASM import section to ensure no undeclared host imports exist

### PackageLoader

Responsibility: take a `VerifiedPackage`, compile its WASM module, and register contracts into the `CapabilityRegistry`.

```rust
pub struct PackageLoader {
    registry: Arc<RwLock<InMemoryCapabilityRegistry>>,
    module_cache: Arc<RuntimeModuleCache>,
}

impl PackageLoader {
    pub fn load(&self, pkg: VerifiedPackage) -> Result<CapabilityId, PackageError> {
        // 1. Compile WASM module (heavy: JIT, validation)
        // 2. Store in RuntimeModuleCache keyed by (CapabilityId, Version)
        // 3. Register each CapabilityContract from manifest into frozen registry
        // 4. Return the primary CapabilityId
    }
}
```

The loader calls `registry.register()` for each contract in the manifest. The compiled module goes into `RuntimeModuleCache`, not the registry — keeping metadata and binary artifacts in separate stores.

### RuntimeModuleCache

```rust
pub struct RuntimeModuleCache {
    modules: RwLock<HashMap<(CapabilityId, Version), wasmtime::Module>>,
}

impl RuntimeModuleCache {
    pub fn get_or_compile(
        &self,
        key: &(CapabilityId, Version),
        engine: &wasmtime::Engine,
        bytes: &[u8],
    ) -> Result<wasmtime::Module, RuntimeError>;
    pub fn evict(&self, key: &(CapabilityId, Version));
    pub fn clear(&self);
}
```

The cache is the single source of truth for compiled WASM modules. It ensures that repeated invocations of the same capability reuse the compiled module, while instances remain ephemeral.

In v0.12, the cache key is `(CapabilityId, Version)`. Future versions may extend the key to include runtime configuration (e.g., engine features, optimization profile) if multiple execution environments are introduced.

### PackageRegistry

Responsibility: store and retrieve `.fusionpkg` files.

```rust
pub trait PackageRegistry: Send + Sync {
    fn store(&self, id: &CapabilityId, version: &Version, pkg: &[u8]) -> Result<(), PackageError>;
    fn load(&self, id: &CapabilityId, version: &Version) -> Result<Vec<u8>, PackageError>;
    fn list_versions(&self, id: &CapabilityId) -> Result<Vec<Version>, PackageError>;
    fn contains(&self, id: &CapabilityId, version: &Version) -> Result<bool, PackageError>;
}
```

Initial implementation: `FilesystemPackageRegistry` — stores packages under a configurable root directory as `{id}/{version}.fusionpkg`.

Future implementations: `S3PackageRegistry` (not part of v0.12). Future registry implementations may also support richer metadata search (capability name, permission sets, tags) while preserving the `PackageRegistry` trait as the minimum required contract.

### Resolution Integration

The existing `CapabilityResolver` already handles capability resolution. When a capability is resolved and its contract has dependencies:

1. The resolver checks the `CapabilityRegistry` for the dependency
2. If the dependency is a `.fusionpkg` capability, the `PackageRegistry` is queried to locate the compiled WASM module
3. The `SandboxRuntime` is called with the module bytes at execution time — not at resolution time

This keeps resolution fast (metadata only) and defers WASM instantiation to execution.

### File Organization

```
src/
  package/
    mod.rs                  — PackageError, re-exports
    format.rs               — .fusionpkg parsing, manifest types
    verifier.rs             — PackageVerifier
    loader.rs               — PackageLoader
    registry.rs             — PackageRegistry trait
    filesystem_registry.rs  — FilesystemPackageRegistry
```

## 7. Developer Platform

### Capability Lifecycle

```
new ──► build ──► test ──► publish ──► dev
                                      │
                                      └── (hot-reload loop)
```

### Commands

#### `fusion new <name>`

Scaffolds a new capability project:

```
my-capability/
  src/
    lib.rs
  Cargo.toml           — configured for wasm32-wasi target
  manifest.toml        — auto-generated from #[capability] macro
  tests/
    integration.rs
```

Uses the existing `PluginScaffolder` infrastructure in `src/devex/scaffold.rs`, extended for WASM target.

#### `fusion build`

```
$ fusion build
  → cargo build --target wasm32-wasi --release
  → post-process: strip wasm section, optimize with wasm-opt
  → package: tar + gzip into .fusionpkg
    → output/my-capability-0.1.0.fusionpkg
```

Produces the packaged artifact. No separate `fusion package` command — build IS packaging.

#### `fusion test`

Runs capability tests in a `NativeSandboxRuntime` with a mock `CapabilityHostServices`:

```rust
pub struct MockHostServices {
    pub emitted_events: Vec<ExecutionEvent>,
    pub logs: Vec<(Level, String)>,
    pub secrets: HashMap<String, String>,
    pub http_responses: HashMap<String, Response>,
    pub metrics: Vec<(String, f64)>,
}
```

Test output is standard `cargo test` augmented with capability-specific diagnostics (permission usage, host call traces).

#### `fusion publish`

```
$ fusion publish ./output/my-capability-0.1.0.fusionpkg --registry <url> --key <signing-key>
  → 1. Sign attestation with provided key
  → 2. Upload to target registry
  → 3. Print published CapabilityId + version
```

#### `fusion dev`

Hot-reload development loop:

```
$ fusion dev
  → watch src/ for changes
  → on change: cargo build → wasm-opt → instantiate in NativeSandboxRuntime
  → serve local HTTP endpoint for manual testing
  → stream capability logs to console
```

These commands may be specified in a later iteration. The `fusion` CLI should print a meaningful "not yet implemented" message for them.

## 8. Operations Platform

### Separation

| Domain | Concerns | Tools |
|--------|----------|-------|
| **Observability** | Dashboard, Runtime Inspector, Metrics, Health | Web UI, existing metrics pipeline |
| **Governance** | Policy management, Attestation verification, Registry admin | Web UI, existing release gates |

### Observability

#### Dashboard

Read-only web UI showing:
- Live registry contents (capabilities, versions, permissions)
- Runtime inspector (loaded instances, memory/fuel usage)
- Capability invocation metrics (latency, error rate, throughput)
- Health status of sandbox runtimes

Integration: consumes existing `FusionMetrics`, `AuditLog`, and `EventBus` — no new telemetry pipeline needed.

#### Runtime Inspector

Per-instance view:
- `SandboxInstance::memory_usage()` and `fuel_consumed()`
- Invocation count, last error, uptime
- Host service call breakdown (how many secrets fetched, HTTP calls made, events emitted)

### Governance

#### Policy Management UI

CRUD interface for:
- Allow/deny lists (existing `PolicyContext` from O2.5)
- Release profile assignments (development/staging/production)
- Waiver management

Integrates with the existing `src/policy/` module — writes policy definitions to the same YAML format.

#### Attestation Verification

Read-only view that:
- Lists published packages and their attestation status
- Shows verification results from `PackageVerifier`
- Re-verification on demand (triggers release gates)

#### Registry Administration

- Package deletion (soft-delete only, retention policy)
- Version deprecation (semver-aware)
- Access key management

### File Organization

```
src/
  operations/
    mod.rs
    dashboard.rs            — Dashboard data providers
    runtime_inspector.rs    — Instance inspection
    policy_admin.rs         — Policy CRUD
    attestation_viewer.rs   — Attestation status view
```

The Operations Platform subsystem delivers only the backend data providers and REST API layer. The frontend (dashboard web UI) is **out of scope for v0.12** and will be defined in a separate specification when frontend work begins. The REST API is designed so a future UI can be added without structural changes to the data providers.

```rust
// Example: Dashboard data provider interface
pub trait DashboardDataProvider: Send + Sync {
    fn registry_summary(&self) -> Result<RegistrySummary, OperationError>;
    fn runtime_summary(&self) -> Result<RuntimeSummary, OperationError>;
    fn invocation_metrics(&self, window: TimeWindow) -> Result<Vec<InvocationMetric>, OperationError>;
}
```

The REST API routes are:
- `GET /v1/operations/registry` → `RegistrySummary`
- `GET /v1/operations/runtime` → `RuntimeSummary`
- `GET /v1/operations/metrics?window=1h` → `Vec<InvocationMetric>`
- `GET /v1/operations/policies` → policy listing
- `POST /v1/operations/policies` → policy create/update
- `GET /v1/operations/attestations` → attestation status

### Test Structure by Layer

| Layer | Tests | Framework |
|-------|-------|-----------|

### Conformance Tests

A suite of test WASM modules exercising:
- Correct capability invocation (JSON in/out round trip)
- Permission enforcement (denied secret access returns error, not data)
- Memory limits (module that allocates beyond limit is killed)
- Fuel exhaustion (infinite loop is killed)
- All 5 host functions return expected results

### Existing Test Infrastructure

All existing tests (852+ in CI) must continue to pass. The old C-ABI plugin tests remain.

## 10. Migration

### What Changes

| Component | v0.11 behavior | v0.12 behavior |
|-----------|---------------|----------------|
| Plugin loading | C-ABI shared libraries (`.so`/`.dll`) | C-ABI **and** `.fusionpkg` |
| Capability execution | Direct trait dispatch | Sandboxed WASM invocation |
| Registry | Mutable, then frozen | Same (unchanged) |
| Resolver | String errors | Typed `ResolverError` (already in O2.5) |
| Permissions | String-based | Typed `Permission` enum (already in O2) |

### Deprecation Path

The old C-ABI plugin system (`PluginManager`, `PluginRegistry`) is **deprecated** in v0.12 but not removed. Removal is targeted for v0.13:

1. v0.12 — both systems coexist. C-ABI plugins emit a deprecation warning at load time.
2. v0.13 — C-ABI code paths are deleted.

### Non-Breaking Guarantees

- Existing `CapabilityContract`, `CapabilityRegistry`, `CapabilityResolver` APIs are unchanged.
- Existing `ExecutionGraph` structure is unchanged — `CapabilityGraphLowerer` already feeds into it.
- Existing test suite passes without modification.

## 11. Architectural Invariants

The following invariants supplement the 16 core invariants from `docs/architecture/invariants.md`:

### Runtime Invariants

1. **Sandbox isolation.** Capability WASM modules have no access to the host system except through declared `CapabilityHostServices` imports.
2. **Deterministic instance creation.** Identical `SandboxRuntime::instantiate(module_bytes, ctx)` with identical `RuntimeContext` produces functionally identical instances.
3. **Ephemeral instances.** Instances are not reused across executions. Each invocation gets a fresh instantiation.
4. **Fair resource accounting.** Memory and fuel limits are enforced per-instance, not per-module.

### Host Interface Invariants

5. **Declared permissions are enforced.** Host functions check the capability's `CapabilityContract.permissions` before servicing requests.
6. **Event correlation.** Every event emitted via `emit_event` is correlated to the originating execution via execution ID in the event envelope.

### Package Invariants

7. **Immutability after publishing.** Once a `.fusionpkg` is stored in a `PackageRegistry`, it is never modified. Updates are new versions.
8. **Verification before loading.** No package enters the runtime without passing `PackageVerifier::verify`.

### Developer Platform Invariants

9. **Build = Package.** `fusion build` always produces a `.fusionpkg`. There is no intermediate build output format.
10. **Dev native runtime is non-production.** `NativeSandboxRuntime` is explicitly a development adapter and MUST NOT be used in production configurations.

### Operations Platform Invariants

11. **Observability is read-only.** The Dashboard and Runtime Inspector never mutate runtime state.
12. **Governance writes are audited.** All policy and registry mutations are recorded in the `AuditLog`.

## Appendix: Implementation Order

| Phase | Subsystem | Dependencies | Rationale |
|-------|-----------|-------------|-----------|
| 1 | Runtime (`SandboxRuntime` + `WasmtimeSandboxRuntime`) | ADR-019 trait definitions | Foundation — everything else depends on sandbox execution |
| 2 | Host Interface (`WasmtimeCapabilityHost` + linker) | Runtime | Must be paired with the runtime — defines the runtime<->capability contract |
| 3 | Package Platform (verifier, loader, registry) | Runtime + existing `CapabilityRegistry` | Needs runtime to verify WASM + registry to register contracts |
| 4 | Developer Platform (CLI commands) | Package Platform | Builds and publishes packages |
| 5 | Operations Platform (UI data providers) | Everything above | Depends on all data sources existing |
| 6 | Conformance tests + E2E tests | All subsystems | Final validation before release |
