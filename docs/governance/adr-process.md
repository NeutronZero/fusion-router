# Governance: ADR Process

## Overview
Every architectural modification, new subsystem introduction, or major contract evolution requires an Architecture Decision Record (ADR) stored in `docs/adr/`.

## Workflow
1. **Draft:** Propose new ADR using standard template (`Context`, `Decision`, `Alternatives`, `Consequences`).
2. **Review:** Ensure proposed change respects AF-003 Laws (1–17) and Invariants (1–10).
3. **Acceptance:** Update `docs/architecture/manifest.yaml` if versioned contracts or laws are incremented.
