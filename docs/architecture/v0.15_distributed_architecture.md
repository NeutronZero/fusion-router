# Architectural Specification — FusionRouter v0.15 Distributed Execution Platform

> **Vision:** Extend FusionRouter from a single-node compiler platform into a **distributed execution platform**. The compiler pipeline (`fusion-compiler`, `fusion-planner`, `fusion-scheduler`) remains frozen and authoritative. A distributed runtime layer surrounds the core, managing Placement, Cluster State, Worker Federation, and Execution Leases.

## 2. Distributed Invariants (v0.15)

### Invariant 13: Single-Worker Lease Exclusivity
Every `ExecutionGraph` node is leased by at most one worker at any instant. Workers execute tasks under explicit, time-bounded leases issued by the Placement Engine; expired or revoked leases revert to the Coordinator for crash recovery.

### Invariant 14: Monotonic Lease Epochs
Worker heartbeats and lease renewals monotonically advance the lease epoch. Out-of-order or stale epoch renewals are rejected by the Coordinator.

### Invariant 15: Side-Effect-Free Offline Replay Simulation
Replaying an execution bundle (`.fusion`) against new placement algorithms or updated cluster state produces zero external provider side effects or duplicate LLM network requests.

## 3. Placement Engine as Core Differentiator

The Placement Engine sits between compilation and worker dispatch, evaluating multi-dimensional cost/capability vectors:

```text
Placement Score = 
   (CapabilityScore × 0.30) + 
   (LocalityScore   × 0.25) + 
   (LoadScore       × 0.20) + 
   (LatencyScore    × 0.15) + 
   (CostScore       × 0.10)
```

This leverages the compiler-driven architecture (`ExecutionGraph`) to make optimal distributed placement decisions without modifying the compiler passes.
