# FusionRouter v0.14.5 — Free-Model Validation Experience

> **Scope**: First live end-to-end validation of the FusionRouter monolith
> against a real workload — analyzing its own codebase — using only free
> LLM providers, with zero paid credits.
> **Date**: 2026-08-08
> **Branch**: `test/bugfix-free-model-routing` → merged to `master` as `067e9c5`

## Executive Summary

FusionRouter successfully compiled and executed a self-analysis
(Planner → Compiler → Scheduler → Executor, 6-node DAG) through the HTTP
chat API using **only free models**. The run exposed three real integration
bugs that the mock-based test suite could not catch; all were fixed and the
run went green on **two independent providers** (OpenRouter `:free` and
OpenCode Zen). No source-level changes were required to support Zen —
it was already a first-class provider; only request-serialization discipline
was needed.

## The Workload

- Full HTTP request: `POST /v1/chat/completions` with a 188K-corpus prompt
  (FusionRouter architecture docs + source) in `mode: exhaustive`.
- Pipeline: Context Assembly → Requirements Extraction → Planner →
  `build_compiler` (4 mandatory passes + strategy expansion) → Scheduler →
  Executor with a 5-node strategy subgraph (consensus members + judge).
- Request artifacts:
  - OpenRouter run: `C:\Users\...\Temp\opencode\fusion_request.json`
  - Zen run: `C:\Users\...\Temp\opencode\fusion_zen_request.json` (model
    `zen/deepseek-v4-flash-free`, same corpus)

## Bugs Found & Fixed

| # | Symptom | Root cause | Fix |
|---|---------|-----------|-----|
| 1 | Strategy LLM nodes failed with empty `messages` (`400 Input required`) | Prebuilt strategy subgraphs (consensus/judge) are materialized at compile time, before request context exists; only top-level nodes got the injected `messages` | `CompilationStep` now injects the assembled messages into **every** LLM sub-node too (`src/server/pipeline.rs`), plus a belt-and-suspenders `DefaultExecutor::propagate_parent_messages` fallback for both prebuilt and runtime-lowered subgraphs (`src/executor/mod.rs`, incl. regression test) |
| 2 | `Stream exceeded timeout` node failures ~185–200 s | OpenRouter transport timeout was 30 s | `HttpTransport::new(Duration::from_secs(600))` (`src/providers/openrouter.rs`) |
| 3 | `Token budget exceeded: 296469 > 200000` | Per-request `BudgetEnvelope` was fixed at quota/5, but each LLM node re-sends the full context | Envelope is now `max(quota/5, (input+output) x LLM-node-count)` with `max_iterations` 10→100 (`src/server/pipeline.rs`) |

Regression coverage: 14 executor tests + 2 pipeline tests pass; full
`cargo build` clean; `scripts/check-memory.py` green.

## Provider Experience Notes

### OpenCode Zen (`https://opencode.ai/zen/v1`)

- **The gateway was never down** — initial `500`s were a client artifact:
  PowerShell `-d '...'` inline JSON bodies get mangled (quote/pipe
  handling) and the gateway returns `500` before parsing. With BOM-free
  JSON files (`[System.IO.File]::WriteAllText(..., UTF8Encoding($false))`
  or the `write` tool) the same requests return HTTP 200 — stream and
  non-stream.
- Model catalog (`GET /zen/v1/models`): `deepseek-v4-flash-free`
  (200K context / 128K output, cost 0) and `deepseek-v4-pro`.
- Reasoning output arrives in `choices[0].message.reasoning_content`
  (not a separate field; no special headers needed — plain
  `Authorization: Bearer` + `Content-Type: application/json` is enough).
- `GET /zen/v1/models` 200; `console.opencode.ai/zen/v1` → 404 (sunset
  endpoint alias).
- FusionRouter routing: `zen/` prefix → ZenProvider (strips `zen/` /
  `opencode/` prefix before sending, `src/providers/zen_model.rs`).

### TokenRouter (`https://api.tokenrouter.com/v1`)

- Verified 200 with free `moonshotai/kimi-k3-free` (responds as
  `kimi-k3`), returns `reasoning_content`; auth via `auth.json` key.
- Not yet wired into this project's provider set.

### OpenRouter

- `:free` models keep long generations — hence the 600 s timeout.
- Model string sent verbatim.

## Tooling / Operational Lessons

- **Windows PowerShell + curl**: pipe JSON bodies through files, never
  inline `-d`. Use `--data-binary "@file"`.
- **BOM**: `Set-Content`/`Out-File` add a UTF-8 BOM which breaks strict
  parsers — use `WriteAllText` with `UTF8Encoding($false)`.
- Test-branch workflow: `test/bugfix-*` branches carry fix commits
  (verified against real providers) before merging to `master` with
  `--no-ff`.
- Server kept running during fixes; stopped stale process before rebuild
  (Windows file lock on `target/debug/fusion-router.exe`).
- `.memory/` handbook updated in lockstep; `check-memory.py` validates
  cross-references before commit.
