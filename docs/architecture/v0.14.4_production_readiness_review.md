# FusionRouter v0.14.4 — Production Readiness & Systems Review

> **Scope**: Production readiness and systems audit of FusionRouter post-unification architecture.
> Evaluates implementation fidelity, distributed systems safety, fault tolerance, telemetry propagation, and performance under operational conditions across all 18 workspace crates.
> **Date**: 2026-08-05

---

## Executive Summary

Following Engine Unification (v0.14.1), Studio Vertical Integration (v0.14.2), and the Distributed Runtime Foundation (v0.14.3), FusionRouter's architecture has matured significantly. The codebase reflects strong domain separation, explicit 3-tier layering, and formal governance constraints (AF-003 through AF-006, Invariants 1–15). 

However, a deep systems audit reveals critical gaps between the **frozen architectural specifications** and their **distributed runtime implementations**. The primary production risks stem from:
1. **Unfenced HA Coordinator Failover**: `promote_to_leader()` uses local in-memory locks without distributed consensus, guaranteeing split-brain under network partitions.
2. **Non-Deterministic Placement Decisions**: `PlacementEngine` generates random `Uuid::new_v4()` and `chrono::Utc::now()` timestamps during placement, breaking deterministic replayability.
3. **Lease Liveness & ABA Epoch Reset**: `ExecutionLeaseManager` ignores TTL expiration and resets lease epochs to 1 upon re-issuance, causing node lockouts when workers crash and exposing the system to ABA race conditions.
4. **Siloed Telemetry & Broken Trace Propagation**: OTEL spans lack `ExecutionId`, `PlacementId`, and W3C context headers across worker boundaries. Operators cannot trace routing rationale via telemetry alone.
5. **Mock-Based Operational Testing**: The test suite validates SLOs and fault tolerance using in-memory mocks (`NoopEvidence`, synthetic `FailingProvider`) rather than real network/process fault injection.

## The Canonical Artifact Transformation Law

FusionRouter's deterministic compilation and replay architecture enforces a fundamental system law:

> **Canonical Artifact Transformation Law**: *Every downstream artifact in the execution pipeline is a pure, deterministic transformation of exactly one upstream artifact.*

```text
WorkflowIR
    │
    ▼
ExecutionGraph
    │
    ▼
PlacementGraph
    │
    ▼
ExecutionPlan
    │
    ▼
ExecutionOutcome
    │
    ▼
ExecutionBundle
```

### Core Rules of the Transformation Law:
1. **Single Parent Origin**: Every artifact has exactly one canonical parent.
2. **Post-Publication Immutability**: Artifact content is immutable after publication.
3. **Recomputation Purity & Identity**: Recomputing an artifact produces:
   - Identical semantic content when inputs are identical.
   - A new artifact identity only when inputs or versioned contracts differ.
4. **Replay Non-Interference**: Replay may observe artifacts but never mutate them.
5. **Execution Lineage Traceability**: Every artifact carries complete lineage back to the originating `ExecutionId`.

## Phase-by-Phase Audit Findings

### Phase A — Architectural Conformance (Static)

#### A1. Studio BFF Service Composition vs. Pipeline Duplication
* **Location**: [`crates/fusion-studio-api/src/lib.rs:637-652`](file:///c:/Projects/fusion-router/crates/fusion-studio-api/src/lib.rs#L637-L652)
* **Severity**: 🟡 **Operational Gap**
* **Evidence Level**: **Verified** (Observed in `chat_handler` source code)
* **Finding**: `chat_handler` in `fusion-studio-api` directly instantiates `CapabilitySystem`, `PlannerService`, `WorkflowBuilder`, and `CompilerEngine` to construct synthetic fallback IRs.
* **Impact & Nuance**: A Backend-for-Frontend legitimately composes backend services. However, constructing synthetic fallback IRs directly inside API handlers introduces a secondary execution path that bypasses the server's primary ingress pipeline.
* **Remediation**: Proxy Studio chat execution requests directly to the core `exec_plane` (`/v1/executions` or `/v1/chat/completions`) to guarantee pipeline parity.

#### A2. Placement Graph & Execution Plan Struct Field Encapsulation
* **Location**: [`crates/fusion-placement/src/lib.rs:60-68, 102-108`](file:///c:/Projects/fusion-router/crates/fusion-placement/src/lib.rs#L60-L68)
* **Severity**: 🔵 **Evolution Opportunity**
* **Evidence Level**: **Inferred** (Static field visibility inference)
* **Finding**: Struct fields on `ExecutionPlan` (`execution_order`, `worker_assignments`) and `PlacementGraph` (`nodes`) are declared `pub` without accessor encapsulation.
* **Impact & Nuance**: Rust ownership and borrow checking enforce immutability unless a `&mut` reference or interior mutability (`Mutex`/`RwLock`) is exposed. While current pipeline code moves these structs without mutating them, wrapping fields with getter accessors prevents future accidental post-compilation mutations.

### Phase B — Runtime & Execution Correctness

#### B1. Placement Engine Determinism: Decision vs. Artifact Identity
* **Location**: [`crates/fusion-placement/src/lib.rs:157-173`](file:///c:/Projects/fusion-router/crates/fusion-placement/src/lib.rs#L157-L173)
* **Severity**: 🟠 **Correctness Risk**
* **Evidence Level**: **Verified** (Direct code inspection of `PlacementId::new()`)
* **Finding**: `PlacementEngine::place()` generates `PlacementId` using `Uuid::new_v4()` and sets `generated_at` to `chrono::Utc::now().to_rfc3339()`.
* **Impact & Nuance**: The multi-dimensional scoring **decision algorithm** itself is deterministic (identical inputs yield identical worker assignments and node scores). However, the **artifact metadata identity** (`PlacementId` and timestamp) is non-deterministic, causing identical runs to produce different `PlacementReport` hashes.
* **Remediation**: Hash `PlacementId` deterministically using UUID v5 derived from `(exec_id, ir_hash, policy_name)` and accept an explicit seed timestamp for deterministic trace generation.

#### B2. Lease Manager Ignores TTL & Resets Epoch on Re-grant
* **Location**: [`crates/fusion-placement/src/lib.rs:216-246`](file:///c:/Projects/fusion-router/crates/fusion-placement/src/lib.rs#L216-L246)
* **Severity**: 🟠 **Correctness Risk**
* **Evidence Level**: **Verified** (Direct code inspection of `grant_lease()`)
* **Finding**: `ExecutionLeaseManager::grant_lease()` enforces single-worker exclusivity by checking `!existing.is_revoked`, but ignores `ttl_ms` or time elapsed. If a worker crashes without calling `revoke_lease()`, the node remains permanently locked. Furthermore, re-granting a lease resets `epoch` to `1` instead of incrementing.
* **Impact**: 
  - **Liveness Failure**: Worker crashes cause permanent node lockouts.
  - **ABA Race Condition**: Resetting `epoch` to 1 allows delayed/stale worker messages from previous lease cycles to be accepted as valid.
* **Remediation**: Check time elapsed against `ttl_ms` to automatically expire dead leases, and monotonically increment `epoch` on every lease re-grant.

### Phase C — Distributed Systems Audit

#### C1. Unfenced HA Coordinator Promotion (Split-Brain Risk)
* **Location**: [`crates/fusion-infrastructure/src/lib.rs:606-611`](file:///c:/Projects/fusion-router/crates/fusion-infrastructure/src/lib.rs#L606-L611)
* **Severity**: 🔴 **Operational Risk**
* **Evidence Level**: **Requires Runtime Validation** (Needs network partition chaos injection to measure split-brain window)
* **Finding**: `CoordinatorHaEngine::promote_to_leader()` promotes local nodes using in-memory `Arc<Mutex>` state without consensus validation or central database fencing.
* **Impact**: Under network partitions or coordinator lag, multiple nodes can simultaneously claim `Leader` status. This leads to dual-active schedulers issuing conflicting execution leases and corrupting state.
* **Remediation**: Implement a fencing token / term epoch mechanism backed by a database-backed lease with monotonically increasing terms (or Raft consensus).

#### C2. Missing Dead Worker Eviction in Registry
* **Location**: [`crates/fusion-worker-protocol/src/lib.rs:52-64`](file:///c:/Projects/fusion-router/crates/fusion-worker-protocol/src/lib.rs#L52-L64)
* **Severity**: 🔴 **Operational Risk**
* **Evidence Level**: **Verified** (Absence of eviction logic in `WorkerRegistryStore`)
* **Finding**: `WorkerRegistryStore` accepts heartbeats and updates `last_heartbeat_at`, but has no background thread or sweep logic to mark stale workers offline or evict them.
* **Impact**: Dead or network-disconnected workers remain in `get_active_nodes()`, causing `PlacementEngine` to assign tasks to defunct workers indefinitely.

### Phase D — Operational Validation & Fault Injection

#### D1. Test Suite Relies on In-Memory Mocks (Zero True Fault Injection)
* **Location**: [`tests/runtime_resilience.rs:19-21`](file:///c:/Projects/fusion-router/tests/runtime_resilience.rs#L19-L21), [`tests/reliability_tests.rs:11-59`](file:///c:/Projects/fusion-router/tests/reliability_tests.rs#L11-L59)
* **Severity**: 🟡 **Operational Gap**
* **Evidence Level**: **Verified** (Audit of `tests/` source code)
* **Finding**:
  - Worker crashes are simulated by manually invoking `lease_manager.revoke_lease()` in unit tests.
  - Provider outages are simulated using a synthetic `FailingProvider` that fails after a fixed call count.
  - Zero tests simulate actual TCP disconnects, packet drops, stale lease races, or worker process crashes.
* **Impact**: The system's resilience claims (Invariant 13, Circuit Breaking) are unvalidated under actual operating conditions.
* **Remediation**: Add integration tests using socket-level fault injection (e.g., Toxiproxy) or process-killing test harnesses.

### Phase E — Observability & Trace Correlation

#### E1. OTEL Spans Omit Core Identifiers & Cross-Boundary Propagation
* **Location**: [`src/scheduler/default.rs:169`](file:///c:/Projects/fusion-router/src/scheduler/default.rs#L169), [`src/telemetry/tracing.rs:1-30`](file:///c:/Projects/fusion-router/src/telemetry/tracing.rs#L1-L30)
* **Severity**: 🟡 **Operational Gap**
* **Evidence Level**: **Verified** (Absence of W3C propagator and span field attributes)
* **Finding**:
  - Tracing spans created in the scheduler and executor instrument `node_id`, but omit `ExecutionId`, `PlacementId`, and `TimelineId`.
  - `telemetry::tracing` initializes tracing subscribers without configuring W3C `TraceContext` propagators.
* **Impact**: Distributed traces break at the worker RPC boundary. An operator cannot query OTEL traces to follow a request from API ingress → Placement -> Worker execution.

#### E2. Routing Rationale Siloed from Telemetry
* **Location**: [`crates/fusion-placement/src/lib.rs:144-154`](file:///c:/Projects/fusion-router/crates/fusion-placement/src/lib.rs#L144-L154)
* **Severity**: 🟡 **Operational Gap**
* **Evidence Level**: **Verified** (Omission of placement attributes from tracing calls)
* **Finding**: `NodePlacementDecision` computes multi-dimensional scores (`locality`, `capability`, `load`, `latency`, `cost`), but these metrics and reasoning strings are never emitted as tracing span attributes or log events.
* **Impact**: An operator **cannot answer** *"Why was Node X assigned to Worker B instead of Worker A?"* using telemetry alone.

### Phase G — Persistence Semantics & Crash Recovery

#### G1. Atomicity of Lease Issuance & Evidence Persistence
* **Location**: [`src/telemetry/sqlite_repo.rs:43-68`](file:///c:/Projects/fusion-router/src/telemetry/sqlite_repo.rs#L43-L68)
* **Severity**: 🟡 **Operational Gap**

## v0.14.5 Milestone Focus: Realistic Validation Under Load

With the 5 core execution engines (`planner`, `compiler`, `placement`, `scheduler`, `runtime`) frozen and governance frozen at AF-003 through AF-006 (no new governance layers or engines), **v0.14.5 will focus exclusively on system validation under realistic operating conditions** across four primary tracks:

### Track 1 — Correctness Under Failure
* Worker process crashes & coordinator failover
* Lease TTL expiry & automatic reallocation
* Network partitions, packet loss & socket timeouts (Toxiproxy)
* Duplicate messages, delayed messages & stale heartbeat eviction

### Track 2 — Long-Running Stability
* 24–72 hour continuous soak execution
* Memory growth & leak detection
* SQLite WAL file size & checkpoint maintenance
* Telemetry log volume & lease table cleanup

### Track 3 — Upgrade & Versioning Validation
* Rolling upgrades across multi-node topologies
* Mixed-version worker & coordinator compatibility
* `.fusion` execution bundle backward/forward compatibility (`tests/compatibility_v1.rs`)
* Schema evolution & fallback deserialization

### Track 4 — Production Performance & Benchmarking
* Realistic 100-node and 500-node execution DAGs
* Mixed real-world provider/network latencies
* Full SQLite WAL, Prometheus metrics, and OpenTelemetry tracing enabled under high concurrent load
